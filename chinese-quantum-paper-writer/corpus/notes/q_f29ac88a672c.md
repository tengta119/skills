## 研究问题与背景

Falcon 是基于格的后量子数字签名算法，被 NIST 选为四种后量子密码标准算法之一。作者指出，Falcon 的密钥生成、签名与验证三个部分中，密钥生成占用计算资源最多，而密钥树生成又是密钥生成的核心部件；已有硬件加速研究多集中在签名验证和关键部件的优化，尚未对 Falcon 密钥树生成部件进行充分的硬件实现研究（p.1–2）。因此论文要解决的是：如何用 GPU 并行加速 Falcon 密钥树生成，在保证结果正确的同时提高吞吐量、减少资源占用（p.1）。

## 方法、假设、核心公式与算法

作者分析了 Falcon 密钥生成流程：通过 ffLDL* 模块与 LDL* 模块逐步计算密钥树，再对节点规范化并封装私钥 sk 和公钥 pk（p.3，图 3）。核心做法是把原本的递归过程改写为迭代并行：以 Falcon 512 为例，密钥树共 1023 个节点，分配 1023 个线程，每个节点对应一个线程函数模块（p.4）。设计包含 6 个阶段：层间串行、层内并行；1023 线程全节点值存储；1023×3×2×2×512 的 Falcon 密钥树存储矩阵 T；奇偶线程联合调度；合并中间变量 L、D、T；设计 roots_dict 矩阵查表（p.4）。在 GPU 内采用粗粒度与细粒度结合的并行：单线程组内用细粒度并行处理单个算法，多线程组间用粗粒度并行处理多个完整后量子算法（p.2–3，图 2）。为减少寄存器溢出，3 层计算均采用无中间变量的直接计算模式（p.5，算法 5）。

## 作者明确提出的贡献

作者自述：提出一种基于 GPU 的 Falcon 密钥树并行生成方案；该方案使用奇偶线程联合控制的单指令多线程（SIMT）并行模式和无中间变量的直接计算模式，达到提升速度和减少资源占用的目的；基于 Python 的 CUDA 平台进行实验，验证结果正确性并做性能分析（p.1）。

## 实验环境、数据、基线与指标

实验平台：Windows 10、CUDA 11.4、Python 3.8、Numba 0.53.1、Intel Core i7-11800H @ 2.3 GHz、NVIDIA GeForce RTX 3060 Laptop；另在 NVIDIA Jetson Xavier NX 嵌入式平台测试（p.5）。基线为 CPU（Intel Core i7-11800H）上的实现；正确性以 NIST 提供的 Falcon 参考 Python 实现为对照（p.5，图 7、图 8）。指标为延迟（ms）、吞吐量（次·s⁻¹）和 GPU/CPU 加速比；测试参数包括 Falcon 512、256、128、64（表 1，p.6），并行粗粒度组件数从 1 到 16384（表 3，p.7）。

## 核心结论与结果

作者报告：在 RTX 3060 Laptop 上，Falcon 512 的 ffLDL* 模块延迟为 6 ms、吞吐量为 167 次/s；计算单个 Falcon 密钥树生成部件时 GPU 相对 CPU 实现 1.17 倍加速；同时并行 1024 个 Falcon 密钥树生成部件时，GPU 相对 CPU 的加速比达到约 56 倍（p.1、p.7）。表 2 显示，随 Falcon 参数 n 降低，ffLDL* 延迟下降、吞吐量上升：RTX 3060 上从 Falcon 512 的 167 次/s 提高到 Falcon 64 的 1000 次/s；Jetson Xavier NX 上从 32 次/s 提高到 Falcon 2 的 526 次/s（p.6）。表 3 显示并行粗粒度组件数为 1024 时 GPU 延迟 128 ms、CPU 延迟 7168 ms、加速比 56.00（p.7）。作者还用 NIST 参考实现对比了密钥树部分数据，称运行结果一致（p.5）。

## 局限与适用边界

作者明确指出：当前 1023 个线程只运行 1 个 ffLDL* 模块，尚未达到 GPU 的最大并行负载；如果加入粗粒度并行，性能还可进一步提升（p.7）。作者也说明研究针对 Falcon 密钥树生成部件，未覆盖签名与验证全流程的端到端性能（p.1–2）。

阅读者推断：实验只在一个桌面 GPU 和一个嵌入式 GPU 上、以单一 CPU 型号为基线，未报告功耗、显存占用或多平台统计显著性；因此“56 倍”是特定参数与实现下的加速比，不能直接外推为所有 Falcon 参数或所有硬件上的通用结论。该推断依据论文的实验设置与结果表，属于阅读者判断。

## 相关工作与潜在研究方向

作者回顾了 Falcon 及后量子算法在 FPGA/ASIC/GPU 上的实现，包括 Dilithium、SPHINCS+、Kyber、NewHope 等；指出 Falcon 因需要浮点复数计算与递归过程，硬件实现难度较高（p.1–2）。作者认为该 GPU 方案可为物联网等分布式终端的后量子数字签名应用提供高效方案（p.8）。
